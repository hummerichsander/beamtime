# MCP tools

Agents connect through `beamtime setup` (or `beamtime mcp install`) and call the same operations as
the [commands](cli.md), each as a tool named like its command path (`note add` is `note_add`). The
setting `mcp_tools: core` lists the 21 core tools plus `tools_more`, which describes and
calls the tools of the families (views, blocks, runs, export); `all` lists all 47.

The `script` tool runs the Python an agent sends with `bt` preloaded: every operation is a function
whose answer is a plain dict, so the operations compute the statistics and Python joins and formats
what they return.

```python
a = bt.importance(from_="scaling/lr-sweep", target="metric.val/acc.max")
for row in a["rows"]:
    print(row["field"], row["eta_squared"])
```

## Not for agents

Agents never run these; they tell you the command instead.

- `beamtime serve`: The web UI and the indexing daemon for this root; --no-ui only indexes.
- `beamtime demo`: Generate a sample log dir and serve it.
- `beamtime setup`: Set up this project and this machine, or change the setup.
- `beamtime mcp install`: Register `beamtime mcp` with an agent client.
- `beamtime settings`: The effective settings and the level each value comes from.
- `beamtime set`: Set theme, theme_mode or figure_style in this project's beamtime.yaml.
- `beamtime doctor`: Check the installation, root, log dir and cache.
- `beamtime reindex`: Rebuild the index from the files.
- `beamtime mv`: Move a run into a group, or move or rename a group; running runs are refused.
- `beamtime rm`: Move a run or group into the trash.
- `beamtime block export`: Copy a library block with every version into <to>/blocks/<name>/.
- `beamtime block import`: Copy library blocks from a project, a folder or a git repository into a group.
- `beamtime pull`: Copy a remote group into a read-only snapshot that answers while it's away.
- `beamtime note rm`: Move a note, with the earlier versions it replaced, into the trash.
- `beamtime gc`: Empty the trash and remove ended runs without metrics (with --yes).
- `beamtime ps`: Every Beamtime process here: serves, index daemons, remotes, MCP servers.
- `beamtime stop`: Stop this directory's serve, or the one for a root, log dir or pid (or all).
- `beamtime source add`: Add a remote: name, host:/path; probes ssh for the command unless given.
- `beamtime source list`: List the configured remotes.
- `beamtime source rm`: Remove a remote from wherever it is configured.
