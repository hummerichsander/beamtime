The first five minutes with Beamtime

A clickable draft of the setup wizard. Pick a scenario and answer with the keyboard or the mouse; the margin explains each step, its flag and where the answer is stored. Lists that come from detection take your own entries too: try “+ Add a path” and “+ Add a host”. Draft 3 adds the agent rules, Beamtime log dirs as a source of past work, and the update path for older setups.

What the draft commits to

    
    
      
  • look first
    Every default comes from the project: git, the Python environment, past logs, notes, agents and ssh hosts. A typical project answers most questions with Enter.
    • 
      
  • yours to extend
    Detection only preselects. Every list it fills also takes your own entries, such as another log dir, a notes folder, memory files or a host, and a typed entry is checked the same way as a found one.
    • 
      
  • many remotes
    Pick any number of machines. They are checked together, then each gets its own path and, if needed, an install. Each becomes a source, such as @juwels or @lab-gpu.
    • 
      
  • no trace
    Nothing is written before the review. ctrl-c at any point leaves the project as it was. Remote installs and imports wait for the review too.
    • 
      
  • one command
    Every answer is a flag. The wizard can end by printing the same setup as one command, for another machine, a script, or an agent to hand to you.
    • 
      
  • two places
    Each answer says where it lands: beamtime.yaml for the team, ~/.config/beamtime for this machine. A teammate who clones the project gets only this machine's questions.
    • 
      
  • presets
    Agent behaviour starts from three presets, and Careful is today's behaviour. Single settings are one step further, for those who want them.
    • 
      
  • the record
    The agent rules say plainly that Beamtime holds the experimental record: agents look things up there and write findings there, not into CLAUDE.md, loose notes or their private memory. The block is generated from the agent settings, so the two never disagree.
    • 
      
  • one command to update
    Data never migrates: every file reads in every later version. What an upgrade changes is the setup around the data (rules, MCP config, skills, settings, remote installs), so rerunning beamtime init is the update, not a separate wizard. In CI or for an agent, beamtime init --check lists what is stale without asking.
    • 
      
  • judgment to agents
    Turning old notes and memory files into typed, linked notes needs judgment. The wizard hands that to the agent you chose and starts it if you ask; it never calls a model by itself.
    • 
      
  • any terminal
    Arrow keys, space and Enter, with numbers as shortcuts. Without a terminal it asks nothing and takes the flags or the defaults. Standard library only, so the CLI stays fast to start.
    • 
      
  • voice
    The app's voice: plain and short, states in lowercase, no emoji and no exclamation marks.
